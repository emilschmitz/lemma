\section{Experimental Results (DuckDB vs GenDB)}
\label{sec:eval-gendb-duckdb}

We report \textbf{DuckDB SQL} latency only. We do not report Lemma-synthesized
executors here.

\paragraph{Setup.}
All runs used GCP Spot VM \texttt{lemma-gendb-r15}: machine type
\texttt{n2-highmem-64} (64 vCPU, 512\,GiB), zone \texttt{us-east1-b}, Debian~12
(\texttt{Linux-6.1.0-52-cloud-amd64}). DuckDB \texttt{PRAGMA threads=64}.
This is \emph{not} GenDB's paper server (2$\times$ Intel Xeon Gold 5218,
384\,GB RAM). Milliseconds are the same protocol on different hardware.

\paragraph{Session-hot protocol (one process).}
Open the database once (\texttt{OPEN\_US} diagnostic). For each query: one
timed cold execution; two untimed warmups; \textbf{median of five} timed
executions $\rightarrow$ \texttt{SESSION\_HOT\_US}. Totals are the sum of
per-query medians (not a single multi-query script).

\paragraph{Workloads.}

        Database \texttt{tpch\_sf10.duckdb}: \texttt{lineitem} 59{,}986{,}052 rows

\paragraph{Published GenDB reference} (arXiv:2603.02081 \S4.2).
SEC-EDGAR six-query total: GenDB 328\,ms, $5.0\times$ vs DuckDB
($\approx$1640\,ms), $3.9\times$ vs Umbra ($\approx$1280\,ms).
Per-query GenDB on SEC: Q4 106\,ms, Q6 88\,ms (other SEC per-query
times unpublished).
TPC-H SF10 subset total: GenDB 214\,ms, DuckDB 594\,ms, Umbra 590\,ms.
Per-query GenDB: Q6 17\,ms, Q9 38\,ms, Q18 74\,ms.

\noindent\textbf{Reading.}
On this VM, DuckDB is faster than the DuckDB totals in the GenDB paper
(1030 vs $\approx$1640\,ms SEC; 437 vs 594\,ms TPC-H), which is expected
given different CPUs and DuckDB versions. Published GenDB C++ still wins
the comparable totals (328 and 214\,ms). TPC-H Q6 is the exception: our
DuckDB 15.7\,ms vs GenDB 17\,ms. Q9/Q18 remain much faster in GenDB
(38/74 vs 152/144\,ms). The r16 draw is a harder six-query mix (3-way
joins); it is not a drop-in substitute for Figure~2's six.

\paragraph{What we did not run.}
No Lemma \texttt{run\_query} / Verus-verified native path; no Umbra /
MonetDB / ClickHouse / PostgreSQL; no agent optimization iterations.
The Spot VM was stopped after harvest.
