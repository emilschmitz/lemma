# TPC-H SF1 and SSB SF1 container runs (Sonnet 5.5, 25 min per attempt): failure log and iteration plan

Source: `research_loop/generated/container_runs/sonnet_{tpch,ssb}_*.log` and the run dirs named in each `RESULT` line.
Every row was read in the mandated order: `workspace/mcp_results/runs/*.json`, `submitted.json`, leftover verify,
`workspace/logs/agent_stream.jsonl` (the Sonnet `thinking` events are empty in the stream, so what the agent was doing is read from its tool calls).
Product-path steps and blame words are those of `AGENTS.md`. "Official" = the full-table timed run; the iterate cap (50k) does not change what the
binary runs on (the declarative pipeline always runs the full pinned tables; `dataset_size` only changes the export of the verify-time slice).

## What every run had in common (read this first)

All 11 failing runs, and the TPC-H wins, ran with `LEMMA_STRING_ENCODING` unset, i.e. **plain strings** (`spec.rs` has no `__dict`; `container_batch.py`
forwards the variable only when the launching shell sets it). Consequences, all visible in the traces:

* The prompt (`_parallel_section`) names `hard/dict_parallel_q1.rs`, `dict_group_count_sum_parallel.rs` and `hard/dict_parallel_q12.rs` in plain mode, but
  `mount_examples` mounts `dict_*` files in dictionary mode only. TPC-H Q1 ran `wc -l dict_group_count_sum_parallel.rs hard/dict_parallel_q1.rs` and got
  `No such file or directory` (stream, t=1392 s). Those are the verified 3.95x (Q1) and 2.4x (Q12) solutions of exactly these two queries.
* The SSB star joins group and order by strings. In plain mode the agent has to hand-build a string dictionary and prove `seq_le` orderings itself
  (Q2.1: `bd: Seq<String>`, `lemma_seq_le_total/antisym`, 600 lines before the first Verus pass on the group-by).
* The recipe routed for every SSB star join and TPC-H Q3/Q9/Q12 is `join_group_sum` (plain) or `dict_join` (dict): a TWO-table nested-loop example. No example
  has the shape fact table scanned once + dimension tables reached by key.
